# 湖心追踪 · 基础版

当前部署目标已改为 Render 免费多人测试，见 [DEPLOY-RENDER.md](DEPLOY-RENDER.md)。`render.yaml` 不创建收费磁盘或数据库；临时 SQLite 数据在实例重启后不保证保留。以下 Railway 文档保留为替代方案。

Railway 部署请阅读 [DEPLOY-RAILWAY.md](DEPLOY-RAILWAY.md)。根目录已包含 Dockerfile 和 Railway 配置；上线前必须为服务挂载 `/data` 数据卷。

面向玄武湖抓人游戏的手机网页。当前只实现一个可演练的基础闭环，不自动执行完整游戏规则。

## 运行

### 无需安装的本机网页体验

`npm run demo:export` 会生成 `dist/湖心追踪-网页体验版.html`。下载后用浏览器打开即可，页面顶部提供示例房间与体验身份切换，可演示公开/私信、感染/治愈和位置共享开关。它不连接服务器、不跨设备同步；所有角色数据均在本机，仅演示消息界面可见性，不提供真实的私信安全隔离。请勿填写敏感信息。定位授权和存储在不同本地文件查看器中的支持情况不同，建议使用桌面 Chrome/Edge/Safari 打开，手机用正式部署版体验更稳定。

以下为真正的多人服务端启动方式。单文件体验版与服务器版的存储、会话完全分离。

需要 Node.js 24 或更新版本，使用内置 SQLite，无第三方依赖，无须 npm install。

```sh
cd /workspace/AI-Learning
npm start
```

默认监听 3000 端口，可用 `PORT`、`HOST` 配置。数据库存放于忽略目录 `data/game.sqlite`，可用 `DATA_DIR` 指定持久化目录。停止后重新运行即可恢复房间和消息；进程启动时清除旧位置共享，避免重新发布陈旧坐标。

通过 HTTPS 反向代理接入后才能在其他手机上使用定位；本机 localhost 属于浏览器允许的安全上下文。部署代理需允许至少 25 秒的长轮询请求。页面消息通过带鉴权的长轮询在变更后立即同步，断线自动重连。

## 试用流程

1. 主持人选择“我是主持人”，输入昵称创建房间，复制六位房间码。
2. 其他设备或独立浏览器会话输入昵称和房间码加入。身份凭证仅保存在当前标签页的 sessionStorage，刷新可恢复；关闭标签页后不保证恢复。不要把正式主持人会话关闭，首版暂不支持转交或身份找回。
3. 发送公开消息；选择一个成员发送私信。私信仅双方及主持人可见，主持人拥有审计权限。
4. 主持人点击成员旁的“确认感染/治愈”，线下核实后确认，所有页面同步身份与公开消息。
5. 可主动开启设备位置共享。关闭共享后，其他成员和主持人都收不到该成员坐标，但其仍可查看其他人共享的位置。位置仅保留当前值，无历史轨迹；45 秒未更新不显示坐标，超过时间并不等同于强制关闭授权。
6. 有危险先现场喊停；安全暂停按钮只发送房间通知，不自动冻结尚未实现的游戏时钟。

## 当前范围

- 房间容量：一名主持人 + 九名玩家。
- 房间、身份、公开/私密消息与感染事件持久化。
- 服务端权限校验、私信筛选、幂等请求，避免重复消息和操作。
- 浏览器授权定位、独立收发权限、共享关闭时清除坐标。
- 手机与桌面响应式布局，微信浏览器需真机进一步验收。

未实现：高德底图/家人地图接入、GPS 距离自动判定、技能卡、自动抓捕防御链、冷却、计时和胜负、答题、微信群通知、后台推送。显示的是设备原始经纬度，接高德前需验证坐标系转换，不能直接当高德坐标使用。

位置上传会在浏览器后台/锁屏后中断，不能依赖网页持续跟踪。首次仅对熟悉成员的小规模演练使用；房间码不是正式活动的完整准入控制，后续需要增加加入审核、会话恢复、房间关闭/清理和完整运营保护。所有现有房间数据会持续保存，演练结束后由部署者清理或删除相应数据库（停止服务后操作）；勿用此版本存放长期敏感信息。
